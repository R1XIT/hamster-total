# Homo Antivirus — дизайн-документ

Дата: 2026-07-27

## Идея

Desktop-питомец хомяк (в духе ChomikBox), живущий поверх рабочего стола Windows, который:
- периодически (и по запросу) сканирует выбранные папки на вредоносные файлы через Windows Defender;
- при обнаружении угрозы спрашивает согласие пользователя и, получив его, "съедает" файл с анимацией (принюхался → съел), отправляя его в корзину;
- позволяет удалить **любой** файл, просто перетащив его на хомяка мышкой — тоже с анимацией поедания, без дополнительного подтверждения.

## Графика — источник и правовой статус

Пользователь самостоятельно нашёл и добавил в `sprites/` GIF-анимации хомяка, стилистически соответствующие ChomikBox (взяты из открытых источников/мемов на Tenor). Ассистент не скачивал и не нарезал кадры из чужого контента — только ссылается на файлы, которые пользователь положил в проект сам. Ответственность за происхождение и права на эту графику лежит на пользователе; в README проекта будет явно указано, что графика хомяка адаптирована из стороннего источника.

## Технологический стек

- **Electron + TypeScript**, упаковка через `electron-builder` (NSIS-инсталлятор под Windows x64, возможен portable-вариант).
- Main process: окно хомяка (прозрачное, `frameless`, `alwaysOnTop`), системный трей, планировщик скана, вызовы Windows Defender, файловые операции.
- Renderer process: конечный автомат анимаций хомяка, приём drag-and-drop, всплывающий пузырь уведомлений/согласия.
- IPC между main и renderer для смены состояния анимации и передачи событий (найдена угроза / перетащен файл / клик пользователя).

### Структура каталогов

```
src/
  main/            — точка входа, окно хомяка, трей, автозапуск
  main/scanner/    — обёртка над Windows Defender (MpCmdRun/Get-MpThreatDetection), планировщик
  main/fileops/    — удаление в корзину, проверка системных путей
  renderer/hamster/— стейт-машина анимаций, компонент хомяка
  renderer/bubble/ — компонент всплывающего пузыря
  shared/          — общие типы IPC-сообщений
assets/
  processed/       — обработанные (прозрачные) спрайты, генерируются build-скриптом, коммитятся
sprites/           — исходные GIF от пользователя (вход для build-скрипта)
scripts/
  process-sprites  — одноразовый Python/Pillow скрипт: убирает белый фон, конвертирует в WebP с альфа-каналом
```

## Ассеты и конечный автомат анимаций хомяка

| Состояние | Файл-источник | Когда играет |
|---|---|---|
| Idle (по умолчанию) | `homo_defoult.gif` | Обычное стояние, зациклено. Уже с честной прозрачностью, конвертация фона не нужна |
| Idle-варианты (редкие) | `homo_randomAnim1.gif`, `homo_randomAnim2.gif` | Изредка вместо обычного idle (случайный выбор одного из двух), затем назад в Idle |
| Засыпание | `homo_sleep/homo_sleep1.gif` | Один раз, после 5 минут бездействия (без взаимодействия мышью) |
| Сон (цикл) | `homo_sleep/homo_sleep2.gif` | Зациклено, пока пользователь не кликнет по хомяку |
| Пробуждение | `homo_sleep/homo_slep3.gif` | Один раз по клику, затем → Idle |
| Перетаскивание хомяка | `homo_drag.gif` | Пока пользователь тащит хомяка мышью |
| Сканирование | `homo_viruschech.gif` | Во время скана Defender'ом (ручного или по расписанию) |
| Поедание файла | `homo_eatsHDD.gif` | Удаление вредоносного файла (после согласия) ИЛИ drag-and-drop любого файла на хомяка |

`homo_eatsHDD.gif` — цельная последовательность "принюхался → съел" (126 кадров), отдельного состояния "нюх" не заводим.

### Пайплайн ассетов (прозрачность)

Только `homo_defoult.gif` имеет честный альфа-канал. Остальные 8 файлов — на сплошном белом фоне. Одноразовый build-скрипт `scripts/process-sprites` (Python + Pillow) при запуске (`npm run process-sprites`) убирает белый фон цветовым ключом со сглаживанием края (feather), конвертирует каждый GIF в WebP-анимацию с полноценным (0–255) альфа-каналом, результат кладётся в `assets/processed/` и коммитится в репозиторий. Рантайм ничего не пережимает при каждом запуске приложения — только загружает готовые файлы.

## Обнаружение угроз (Windows Defender)

- Интеграция через `MpCmdRun.exe -Scan -ScanType 3 -File "<путь>"` (точечный скан файла/папки), результат подтверждается опросом `Get-MpThreatDetection` (PowerShell) за последние секунды по совпадению пути; `ThreatName` берётся оттуда для текста уведомления.
- Если Defender недоступен/выключен (стоит сторонний AV) — уведомление в трее об этом, автоскан не работает; drag-and-drop-удаление при этом продолжает работать (оно не зависит от Defender).
- **Ручной скан:** клик по хомяку / пункт трея «Сканировать сейчас» → скан папок из настроек → анимация `homo_viruschech.gif` на время скана.
- **Авто-скан по расписанию:** таймер в main-процессе, по умолчанию раз в 6 часов, папки по умолчанию — Загрузки и Рабочий стол; список папок и интервал настраиваются в окне настроек.
- **При обнаружении угрозы:** хомяк в Idle, рядом всплывает пузырь: «Нашёл подозрительный файл: `<имя>` (`<путь>`). Похоже на `<ThreatName>`. Удалить?» с кнопками **Удалить** / **Оставить**.
  - «Удалить» → анимация поедания → `shell.trashItem()` (корзина).
  - «Оставить» → пузырь закрывается, файл помечается «проигнорирован» на текущую сессию приложения (повторно не спрашиваем о нём до перезапуска).

## Удаление файлов drag-and-drop

- Окно хомяка принимает системный drag-and-drop; путь файла получается через `webUtils.getPathForFile`.
- Файл, перетащенный на область хомяка, удаляется **сразу**, без дополнительного подтверждения (сам жест перетаскивания — согласие): анимация `homo_eatsHDD.gif` → `shell.trashItem()`.
- Ограничения безопасности:
  - Принимаются только отдельные файлы, не папки целиком (защита от случайного «скармливания» всей папки).
  - Пути внутри системных директорий (`C:\Windows`, `C:\Program Files` и т.п.) отклоняются: пузырь «Это системный файл, я его не трону», удаления не происходит.
- Вредоносный файл после согласия в пузыре удаляется тем же механизмом (`shell.trashItem()` + анимация поедания).

## Трей, автозапуск, настройки

- Иконка в трее (на основе кадра хомяка), меню: «Сканировать сейчас», «Настройки», «Запускать при старте Windows» (чекбокс), «Выход».
- Окно настроек: список папок для авто-скана (добавление/удаление), интервал авто-скана, таймаут до сна.
- Автозапуск через `app.setLoginItemSettings()`.
- Конфиг хранится как JSON в `app.getPath('userData')` (через `electron-store`), без БД.
